# Временный интерактивный предпросмотр

Проверено 16 октября 2026 года (Москва). Владелец запросил временную ссылку на работающий сайт и отдельно запретил пока публиковать GitHub Pages.

Повторная проверка **16 октября, 22:25 МСК**, после сообщения владельца о разрешённом интернете: `https://api.trycloudflare.com`, `https://en.wikipedia.org/wiki/AK-47` и `https://www.iwm.org.uk/collections` вновь вернули от прокси **CONNECT tunnel failed, response 403**. Чтение ветки репозитория через штатный Git прошло успешно. Это не отсутствие разрешения владельца: фактический сетевой путь к указанным доменам продолжает отклонять запросы. Публичная временная ссылка по-прежнему не получена.

## Что действительно запущено

Текущая production-сборка создана в `dist`. В облачной машине запущен `npm run preview -- --host 127.0.0.1 --port 4174 --strictPort`. Это настоящая интерактивная WebGL-сцена. Адрес доступен внутри машины и не является ссылкой для телефона. Процесс может завершиться при остановке или восстановлении среды.

Встроенного инструмента внешнего доступа к порту в текущем наборе инструментов нет. Возможность автоматического предпросмотра через интерфейс не объявляется существующей.

## Попытка внешнего доступа

1. HTTP-проверка `https://api.trycloudflare.com` через предоставленный сетевой прокси завершилась `CONNECT tunnel failed, response 403`. Повтор с расширенными разрешениями команды дал тот же результат.
2. Из официального GitHub Release Cloudflare по HTTPS загружен `cloudflared` версии **2026.10.1**. Файл находится вне репозитория: `/workspace/atlas-preview-tools/cloudflared`. TLS-проверка не отключалась. Версия подтверждена самим клиентом.
3. Запуск Quick Tunnel завершился до выдачи URL:

```text
failed to request quick Tunnel: Post "https://api.trycloudflare.com/tunnel":
dial tcp: lookup api.trycloudflare.com ... read: connection refused
```

Нативный клиент не получил DNS-доступ, а запрос через штатный HTTP-прокси был запрещён. Это два фактических результата; доступность исходящих соединений туннеля не подтверждена. Аккаунт, токен и платный сервис не создавались. Внешняя ссылка не получена.

## Подготовленные настройки среды

Существующие домены сохранены. В черновик сетевых настроек добавлены:

- `api.trycloudflare.com`;
- `*.trycloudflare.com`;
- `*.argotunnel.com`.

Инструмент подтвердил сохранение черновика и вернул `requires_publish: true`. Пользователю нужно проверить и сохранить изменения в настройках облачной среды, затем опубликовать **версию среды** через интерфейс продукта. Это отдельная операция от публикации сайта. Сохранение черновика само по себе не изменило текущую сеть.

После применения настроек агент должен повторно проверить доступ, DNS и возможность исходящего соединения клиента. Открытие доменов не гарантирует поддержку требуемого сетевого протокола этой средой. Если клиент заработает, наружу следует направить только production-preview с содержимым `dist`, проверить выданный HTTPS-адрес в браузере и лишь затем передать его владельцу.

Если среда не поддерживает ни внешний доступ к порту, ни исходящий туннель, временная ссылка из этой среды технически недоступна. GitHub Pages не включать как обход этого запрета. Скриншот и внутренний адрес не выдавать за интерактивный предпросмотр.
