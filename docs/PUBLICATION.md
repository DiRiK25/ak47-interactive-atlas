# Сохранение и публикация

## Сохранение в GitHub

Исходники, документация, конфигурация, собственные снимки экрана и `AK47-Interactive-Atlas.zip` отправлены в ветку `codex/ak47-museum-atlas` репозитория `DiRiK25/ak47-interactive-atlas` через штатный Git HTTPS proxy.

GitHub подтвердил создание ветки. Основная ветка `main` автоматически не заменялась. Для принятия изменений откройте:

https://github.com/DiRiK25/ak47-interactive-atlas/pull/new/codex/ak47-museum-atlas

Нажмите **Create pull request**, затем **Merge pull request → Confirm merge**, когда GitHub разрешит слияние. Если включены обязательные проверки репозитория, дождитесь их завершения.

Попытка автоматически создать черновик Pull Request командой `gh pr create` завершилась:

```text
Post "https://api.github.com/graphql": Forbidden
```

Ранее чтение API также возвращало `Forbidden`. Это ограничение сетевого пути к GitHub API; оно не помешало фактической отправке ветки обычным Git. Наличие credential binding было проверено без вывода значения. Дополнительный токен не запрашивался.

## Статус сайта

Публичная HTTPS-публикация из облачной среды не выполнялась. Сборка готова; Vercel-конфигурация и вручную запускаемый Pages workflow находятся в репозитории. Доступного авторизованного подключения к Vercel/Netlify в этой сессии нет.

При повторной проверке ожидаемого адреса `https://dirik25.github.io/ak47-interactive-atlas/` облачный прокси вернул `CONNECT tunnel failed, response 403`. Это не ответ самого сайта: он не подтверждает ни включение, ни отсутствие Pages. Фактический статус публикации нужно смотреть через **Settings → Pages → Visit site**.

Для Vercel после слияния ветки: https://vercel.com/new → вход через GitHub → импорт этого репозитория → **Deploy**. Команда сборки `npm run build`, выходная папка `dist`; ключи и переменные не требуются. Открывать результат следует через кнопку **Visit** после успешной публикации.

Для короткой публикации с телефона подготовлена ветка `codex/static-site` с содержимым `dist` и `.nojekyll`. Исходная рабочая ветка при этом не меняется. В GitHub откройте **Settings → Pages → Source: Deploy from a branch → Branch: codex/static-site → / (root) → Save**. После успешного развёртывания нажмите **Visit site**. Доступность Pages зависит от типа репозитория и тарифа GitHub. Ветка — готовый снимок, а не автоматически обновляемая сборка.

Альтернатива с workflow после слияния исходников: в GitHub **Settings → Pages → Source: GitHub Actions**, затем **Actions → Опубликовать на GitHub Pages → Run workflow** на `main`. Откройте HTTPS-адрес, который вернёт завершённое задание публикации. Сам workflow не был запущен из этой среды.

## Повторное использование облачной среды

В черновик конфигурации сохранены `install_script` и `start_skill`: установка по lockfile, проверки, сборка и запуск dev-сервера в существующем checkout. Также сохранены дополнительные домены для будущего музейного исследования. Черновик не применяет изменения к текущей сети и не публикует сайт. Для переиспользования настроенной облачной среды изменения просматриваются и сохраняются в её настройках, затем среда публикуется через интерфейс продукта. Это отдельная операция от публикации веб-сайта на Vercel.
